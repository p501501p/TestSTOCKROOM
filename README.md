# TestSTOCKROOM

เอกสารและชุดทดสอบ API/Performance ด้วย [Apache JMeter](https://jmeter.apache.org/) สำหรับระบบจัดการสินค้า STOCKROOM

> Repository นี้เก็บเอกสารและไฟล์แผนทดสอบ JMeter ไม่ได้รวมซอร์สโค้ดของเว็บแอปพลิเคชัน

## ภาพรวมระบบ

ระบบ STOCKROOM แบ่งการทำงานเป็น 3 ส่วนหลัก:

1. **Frontend:** หน้าแรก หน้าเข้าสู่ระบบ หน้าสมัครสมาชิก และหน้าจัดการสินค้า
2. **Application/API:** Next.js Server Actions และ API Routes ใช้ตรวจสอบสิทธิ์ ตรวจสอบข้อมูล และเชื่อมต่อฐานข้อมูล
3. **Database:** PostgreSQL จัดเก็บข้อมูล โดยใช้ Prisma เป็น ORM

ข้อมูลหลักประกอบด้วยผู้ใช้ (`User`) และสินค้า (`Product`) บทบาทผู้ใช้มี `ADMIN` และ `USER` โดยอีเมลผู้ใช้และรหัสสินค้าต้องไม่ซ้ำกัน ข้อมูลสินค้าตรวจสอบด้วย Zod ทั้งในฟอร์มและ API

## API สินค้า

| Method | Endpoint | การทำงาน | สิทธิ์ |
| --- | --- | --- | --- |
| `GET` | `/api/products` | อ่านและค้นหาสินค้า (ใช้ query `q` สำหรับค้นหา) | ผู้ใช้ที่เข้าสู่ระบบ |
| `POST` | `/api/products` | เพิ่มสินค้า | `ADMIN` |
| `GET` | `/api/products/[code]` | อ่านสินค้าตามรหัส | ผู้ใช้ที่เข้าสู่ระบบ |
| `PUT` | `/api/products/[code]` | แก้ไขสินค้าตามรหัส | `ADMIN` |
| `DELETE` | `/api/products/[code]` | ลบสินค้าตามรหัส | `ADMIN` |

## วิธีเตรียมและรันทดสอบ

### สิ่งที่ต้องมี

- Apache JMeter 5.6.3 หรือเวอร์ชันที่เข้ากันได้
- URL ของระบบทดสอบที่ได้รับอนุญาตให้ใช้งาน
- สำหรับคำขอที่ต้องใช้สิทธิ์: Session Cookie ที่ยังใช้งานได้จากบัญชี `ADMIN` ของระบบทดสอบ
- - **Email:** admintest@email.com
- **Password:** admin123
- **Role:** `ADMIN`

### ตั้งค่าแผนทดสอบ

1. เปิดไฟล์ `.jmx` ที่ต้องการใน Apache JMeter
2. เลือก **Test Plan → User Defined Variables**
3. ตั้งค่าตัวแปรก่อนรัน:

   | ตัวแปร | ค่าที่ต้องกำหนด |
   | --- | --- |
   | `HOST` | โฮสต์ของระบบทดสอบ โดยไม่ใส่ `https://` |
   | `PROTOCOL` | `https` หรือ `http` ตามการตั้งค่าระบบ |
   | `AUTH_COOKIE_VALUE` | ค่า **Value** ของ Session Cookie สำหรับบัญชี `ADMIN` (ใส่เฉพาะค่า ไม่ต้องใส่ชื่อคุกกี้) |
   | `PRODUCT_CODE` | รหัสสินค้าที่ใช้ในแผน API; กำหนดเป็นรหัสที่ไม่ชนกับข้อมูลจริง |

   ตัวแปร `AUTH_COOKIE_VALUE` ใช้กับแผน API และควรเปลี่ยนค่า placeholder ที่อยู่ในไฟล์ก่อนทดสอบ แผนปัจจุบันส่งคุกกี้ในรูปแบบ `__Secure-authjs.session-token=${AUTH_COOKIE_VALUE}` หากชื่อคุกกี้ของระบบเป้าหมายต่างออกไป ให้แก้ค่าใน **HTTP Header Manager** ให้ตรงกับระบบนั้น

4. บันทึกแผนทดสอบ แล้วกด **Start** เพื่อรัน
5. ตรวจสอบผลจาก **Summary Report** หรือ **View Results Tree** และบันทึกผลไว้ในไฟล์ `.jtl` หากต้องการนำไปวิเคราะห์ต่อ

### รัน Performance Test อย่างปลอดภัย

1. เริ่มทดสอบด้วย TC1 แล้วค่อยเพิ่มระดับไป TC2 และ TC3
2. ตั้ง `HOST` ให้ชี้ไปยังระบบทดสอบที่คุณเป็นเจ้าของหรือได้รับอนุญาตจากผู้ดูแลระบบอย่างชัดเจน
3. ตรวจสอบจำนวนผู้ใช้และ ramp-up ใน Thread Group ก่อนเริ่มทุกครั้ง
4. หลีกเลี่ยงการยิงโหลดไปยังระบบ Production หรือบริการของบุคคลอื่นโดยไม่ได้รับอนุญาต

## การใช้ Session Cookie

1. เปิด Developer Tools ของเบราว์เซอร์ (`F12`) แล้วเลือก **Application → Storage → Cookies**
2. เลือกโดเมนของระบบทดสอบ และคัดลอกค่า **Value** ของ Session Cookie
3. นำค่าไปใส่ใน `AUTH_COOKIE_VALUE` ของ JMeter

อย่าเผยแพร่รหัสผ่านหรือ Session Cookie ใน README, repository, ภาพหน้าจอ, ไฟล์ผลลัพธ์ หรือรายงาน เพราะ Session Cookie ใช้ยืนยันตัวตนได้เหมือนข้อมูลลับ
